# Owner review, 11 Oct 2026: everything to fix before the next release

Nothing here ships until the owner has checked it locally. No deploy, no release.

## A. App: downloads list and detail

A1. **File deleted from disk.** Today: Open shows a toast ("The file is no longer at …"). Wanted: when a finished download is selected, check the file; if it's gone, show "File missing" in the detail with **Download again** (same link and name) and **Remove from list**; Open / Show in Finder disabled; a small "missing" mark in the list.

A2. **Row actions in the list.** Each row gets small icon buttons on hover/focus: **Show in folder** and **Delete/Remove** (finished), **Pause/Resume** (active). Keyboard reachable.

A3. **"More options" when open** reads "Fewer options" (Hindi too).

A4. **Pause responds instantly.** Today the row stays "Downloading" ~5 s until every connection has stopped. Show "Pausing…" at once and lock the button; the engine finishes stopping in the background.

A5. **"Waiting" for minutes, then a jump in progress.** A new download sat in Waiting while another took the slot, then showed lots already done. Show *why* it waits ("Waiting for a free slot: 2 running. Start now?") and keep progress truthful while waiting.

A6. **Duplicate downloads of the same link.** Ubuntu ended up twice ("…iso" and "…(1).iso") though the owner clicked once; the YouTube video ended up as three 172 MB entries. Causes to confirm: (a) the extension can offer the same browser download twice (page auto-start + "download now", or a retry after a slow answer); (b) the app has no "same link already here" check for offers; (c) the video/audio join (`media_jobs::join_finished`) reads and saves the pending joins without a lock, so two calls can both join. Fix all three: one job per link unless the person asks for another copy; join guarded so it runs once.

## B. App: video pages ("Get the video")

B1. **Bring Fuselane to the front.** Any request from the extension (Get video, Download now, a handed-over download) opens or shows the window and focuses it (`show_main`). If the app was closed, the extension starts it (`fuselane://open`) and the request waits for it.

B2. **Never show the previous page's video.** Today the dialog shows the old page for ~10 s. Clear it the moment a new page is asked for.

B3. **Instant, with a proper loader.** Finding qualities runs yt-dlp, which takes seconds. Show a designed loader at once (animated brand ring, the page title as soon as known). Make it faster: start looking as soon as the extension popup opens on a video page, and remember results per link for a few minutes so Back / reopening is instant.

B4. **Back from the qualities goes to a plain "New download" with the YouTube link.** Give a clear way back to the qualities ("Back to video qualities"), from the remembered result, not a new search.

B5. **HD = video + separate audio.** YouTube sends 1080p+ as two streams, so two downloads appear (a group) and an `.m4a`. Show it as **one** item ("2160p video, joining sound…"), keep the two parts hidden, join them, delete the parts. If the audio part is cancelled/removed: offer "Save video without sound" or "Get sound again", never leave a silent file pretending to be done.

## C. App: Continue on another computer (handoff)

C1. **Send only what's downloaded.** The partial file is pre-sized to the full size (`download.rs` `set_len(total)`), so 6 GB went over the network instead of ~1.8 GB. Send the secured byte ranges only.

C2. **Show it on the other computer at once.** The receiver imports only after the last byte today. New: the manifest goes first; the download appears there immediately ("Arriving from ARSH…").

C3. **Start right away on the other computer.** It downloads the never-downloaded parts from the internet while the downloaded parts arrive from this computer, into the same file.

C4. **A dropped connection loses nothing.** Whatever arrived is kept; the rest comes from the internet.

C5. **Resume after a handoff.** It sat "Waiting" until "Start next"; the ring was right but the text said 6% then 4.1%. The progress text must start from what's already secured; Resume must start it (not queue it behind others silently).

C6. **Progress in the dialog.** While sending, the dialog shows "Sending 1.2 of 1.8 GB" with Cancel, and a link to the Send page; it can be closed and the transfer continues.

C7. **Finding the other computer.** Nearby starts when the app starts (visible to trusted computers only). If no computer shows, the dialog says what to do on the other one; after the first "Trust", they always see each other.

## D. Extension (bridge only, for now)

D1. **Why Chrome starts first, then "Cancelled".** A browser extension only learns of a download after the browser has created it, so Fuselane pauses it, asks the app, then cancels and erases it. The erase isn't always happening (entries stay as "Cancelled"). Fix: erase reliably; for links clicked in the popup/context menu nothing reaches the browser at all.

D2. **Downloads in the extension.** Popup shows active downloads with progress, Pause/Resume/Cancel, recent history, Open / Show in folder / Remove. Needs new local-API methods (`jobs.list`, `jobs.watch`, `job.pause|resume|cancel|open|reveal|remove`) behind the existing native-messaging trust.

D3. **Fast and live.** Popup state comes from the app as soon as it opens (no several-second lag); progress updates live.

D4. **The switch "Hand big downloads to Fuselane".** Off = the browser downloads it itself (the extension never downloads). Keep, word it plainer.

D5. **Extension-only downloading (no app).** Not now (owner: keep the extension a bridge). Noted for later: a "lite" mode could split one download into parallel parts on one network and resume it, but can't combine networks (browsers can't choose the network), and very large files are fragile inside a browser.
